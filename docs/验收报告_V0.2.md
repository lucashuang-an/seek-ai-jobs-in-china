## 3. 本轮修复的缺陷

| 缺陷 | 严重度 | 修复 |
|---|---|---|
| `import-scores` 要求 weight 字段，Agent 产出的评分 JSON 无法入库 | 高（链路阻断） | `DimensionScore.weight` 改为可选，缺省从 `configs/scoring.yaml` 读取；未知维度显式报错 |
| `export --format markdown` 崩溃（evidence 以 dict 访问对象属性） | 高（链路阻断） | `build_research_report` 支持 `as_models`，导出层统一使用模型对象 |
| 两条均无 JD 的同公司同城岗位相似度误判为 1.0，被错误合并 | 高（数据丢失） | 空 JD 文本相似度返回 0.0 |
| job id 冲突时后者静默覆盖前者（不同岗位共用 id 导致数据丢失） | 中 | 导入时检测同 id 不同岗位，派生稳定后缀保留两条记录；示例数据 4 处 id 冲突已改名 |
| evidence 检索时间入库后被 `now()` 静默替换 | 中（违反证据规范） | `list_evidence` 恢复持久化的 retrieved_at |
| 公司 created_at / updated_at / last_verified_at 读取后丢失 | 中 | `_company_from_row` 恢复时间戳 |
| Global Remote 岗位被静默过滤（方案 1.4 要求保留待核验） | 中 | 保留入库，状态标记 Unknown（地点待核验），CSV/导出可见 |
| Markdown 表格遇 `|`/换行破坏布局；None 值泄漏到报告 | 低 | 单元格转义；None 显示为 `-`/中文提示；评分维度显示中文标签 |
